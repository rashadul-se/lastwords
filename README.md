# Elder Care Centre (1000 residents)

Layers: `domain` (data) -> `infrastructure` (Postgres, Redis, SQLite outbox) -> `services` (CareService facade, InsightEngine) -> `ui` (Streamlit). Wiring in `app/container.py`.

## Run locally
    docker compose up --build        # http://localhost:8501 (auto-seeds 1000 residents)

## Deploy on Render
1. Push to GitHub. 2. Render > New > Blueprint > select repo (uses `render.yaml`).
Render runs the Docker image natively; `k8s/` is for your own cluster (EKS/GKE/AKS).

## Offline
Toggle "Work offline": events save to the local SQLite outbox, then "Sync now" pushes them to Postgres in batches (idempotent via event_id).

## Admissions, finance, points
- **Admissions:** register a resident, check in/out with date+time (`CARE_TZ` sets timezone). Registering needs the database (new ID); check-in/out work offline.
- **Finance:** income/expense ledger, auto receipt numbers (`RC-YYYYMMDD-XXXXXX`), downloadable receipt, statements, monthly summary.
- **Points:** +50 welcome, +10 per night on check-out, +1 per 100 paid (resident income). Tiers: Member, Silver 500, Gold 1500, Platinum 3000. Manual award/redeem via `CareService.award_points`.
- Existing database: schema upgrades automatically (`ALTER ... IF NOT EXISTS`). For fresh demo data run `docker compose down -v` first.
- Env: `CENTRE_NAME`, `CURRENCY`, `CARE_TZ`.

## REST API for other organisations (`app/api`)
Run: `docker compose up --build` -> http://localhost:8000/docs (interactive OpenAPI). On Render it is the `eldercare-api` service.

**Onboarding flow (the request pool)**
1. Organisation: `POST /v1/subscription-requests` -> `request_id` + `status_token` (shown once; keep it).
2. Platform admin reviews: `GET /v1/admin/requests` (default `PENDING`), then `POST /v1/admin/requests/{id}/approve` (optionally `{"plan":"STANDARD"}`) or `.../reject`. Approval creates the organisation and its own isolated database schema.
3. Organisation polls `GET /v1/subscription-requests/{id}` (header `X-Request-Token`) and, once `APPROVED`, calls `POST .../claim-key` **once** to receive its API key. Only a hash of the key is stored.
4. Use the key: `X-API-Key: ecp_...` on `/v1/residents`, `/v1/finance/*`, `/v1/inventory`, `/v1/procurement/orders`, `/v1/hr/employees`, `/v1/dashboard`, `/v1/me`.

Admin calls send `Authorization: Bearer $PLATFORM_ADMIN_TOKEN` (generated by Render; set it yourself in compose/k8s). Admins can also issue extra keys with a restricted role (`POST /v1/admin/orgs/{id}/keys {"role":"VIEWER"}`), revoke keys, and suspend/reactivate organisations.

**Plans & limits** (`GET /v1/plans`): FREE 60 req/min & 10k/month, STANDARD 300 & 500k, ENTERPRISE 1200 & 10M. Limits are per organisation across all its keys; responses carry `X-RateLimit-*`, and 429 carries `Retry-After`. Counters live in Redis (approximate per-process fallback if Redis is down; monthly counts reset if Redis is flushed). Public sign-ups are limited to 5/hour per IP.

**Isolation:** every organisation gets schema `org_<id>_<slug>`; each request's DB connection has `search_path` pinned to that schema only, and Redis keys are namespaced per tenant.

Tests (no DB needed): `python tests/test_platform_service.py`.
Env: `PLATFORM_ADMIN_TOKEN`, `PLATFORM_SCHEMA`, `CARE_DEFAULT_SCHEMA` (schema used by the Streamlit UI, default `public`), `OUTBOX_DIR`.

## Run on Fedora (docker or podman)
    ./scripts/run-fedora.sh up        # builds Dockerfile.fedora, starts Postgres, Redis, UI (:8501), API (:8000)
    ./scripts/run-fedora.sh status | logs api | token | down | destroy
Secrets are generated into `.env.fedora` (git-ignored via .dockerignore; add it to .gitignore too).
